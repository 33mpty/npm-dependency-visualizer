# Визуализатор npm-зависимостей

Практическая работа № 2 по конфигурационному управлению, вариант 3, страницы 14–16 методички. Программа читает CSV, получает метаданные через HTTP и строит граф версий npm-пакетов. Для учебных графов интернет не нужен.

Исходный код расположен в `src/depviz/`.

## Запуск

Распакуйте архив и откройте терминал в каталоге `npm-dependency-visualizer`. Нужен Python 3.9 или новее. Для SVG установите [Graphviz](https://graphviz.org/download/) и проверьте, что команда `dot -V` доступна из терминала. Пакеты Python устанавливать не требуется. Node.js и npm нужны только для независимого сравнения.

macOS и Linux:

```sh
./run.sh --config examples/cycle.csv --open
```

Windows PowerShell:

```powershell
.\run.bat --config examples/cycle.csv --open
```

`--open` показывает SVG в браузере. Без флага программа сохраняет изображение и печатает путь к нему. Для работы без Graphviz используйте `--dot-only`. Файлы создаются в `out/`, каталог можно сменить через `--output-dir`. При повторном построении графа для того же пакета и версии в том же каталоге файлы перезаписываются. Запуск без аргументов строит граф `is-odd@3.0.1` из реестра.

## Формат CSV

Кодировка UTF-8 (допускается BOM), разделитель запятая. Первая строка `key,value`. Каждый ключ указывается ровно один раз.

| Ключ | Значение |
| --- | --- |
| `package` | Имя npm-пакета, в том числе `@scope/name`. В тестовом режиме имя состоит из заглавных латинских букв |
| `repository` | Базовый URL npm Registry или путь к JSON. Относительный путь считается от каталога CSV |
| `test_mode` | `true` для JSON, `false` для реестра |
| `version` | Точная версия SemVer, например `3.0.1` |
| `ascii_tree` | `true` для печати дерева на этапе 5, `false` для вывода только путей к файлам |

Пример тестового репозитория `{"version":"1.0.0","packages":{"A":["B"],"B":[]}}`. Все его пакеты используют одну указанную версию. Каждая вершина, на которую есть ссылка, должна присутствовать в `packages`.

При неверном CSV, недоступном файле, ошибке реестра или отсутствии версии программа пишет причину в stderr и возвращает код 2. Чтобы показать проверку пяти полей, меняйте их по одному в копии `examples/is-odd.csv` на `broken package`, `file:///tmp/repo`, `maybe`, `^3.0.1` и `yes` соответственно, затем запускайте этап 1. Автоматический тест повторяет эту проверку.

## Демонстрация пяти этапов

| Этап | Аргументы для `./run.sh` или `run.bat` | Что показать |
| --- | --- | --- |
| 1 | `--stage 1 --config examples/is-odd.csv` | Пять строк `ключ=значение`, затем ошибка для испорченного поля |
| 2 | `--stage 2 --config examples/is-odd.csv` | `is-odd@3.0.1` объявляет `is-number: ^6.0.0` |
| 3 | `--stage 3 --config examples/cycle.csv` | BFS печатает A, B, C, D, сохраняет ребро C → A и сообщает о цикле |
| 3 | `--stage 3 --config examples/diamond.csv` | Два пути к D, цикл отсутствует. В `isolated.csv` только A |
| 4 | `--stage 4 --config examples/diamond.csv --target D --transitive` | B, C и E зависят от D напрямую, A достигает D через B или C |
| 4 | `--stage 4 --config examples/cycle.csv --target A --transitive` | C зависит от A напрямую, B транзитивно |
| 4 | `--stage 4 --config examples/isolated.csv --target A` | Обратных зависимостей нет |
| 5 | `--stage 5 --config examples/is-even.csv --open` | SVG и ASCII показывают цепочку из пяти версий пакетов |

Для этапа 5 повторите команду с `examples/is-odd.csv` и `examples/escape-string-regexp.csv`. В `examples/verified/` уже лежат DOT и SVG для всех трёх пакетов. Дерево показывает `[cycle]` для возврата к предку текущей ветви и `[seen]` для вершины, которая была развёрнута в другой ветви.

## Что объяснить на защите

- В `registry.py` стандартный `urllib` получает JSON с метаданными пакета. Для точной версии читается `versions[version].dependencies`. Для транзитивных рёбер `semver.py` выбирает наибольшую опубликованную версию, подходящую под диапазон. Кэш хранит один ответ на имя пакета за запуск.
- В `graph.py` вершина является парой `(имя, версия)`. BFS берёт вершины из начала очереди `deque`. Множество `seen` пополняется при постановке в очередь. Поэтому каждая вершина обрабатывается один раз, а все рёбра сохраняются. Для обнаружения цикла программа удаляет вершины с нулевой входящей степенью. Если часть вершин остаётся, в графе есть цикл.
- Для обратных зависимостей рёбра инвертируются. На первом шаге получаем непосредственных родителей, а `--transitive` запускает тот же BFS по перевёрнутым рёбрам. В JSON поиск идёт по всему тестовому репозиторию, поэтому находится E, недостижимый из A. В реальном режиме область поиска ограничена графом, построенным от корня из CSV. Можно указать имя или конкретную версию в виде `--target name@version`.
- `visualize.py` описывает вершины и рёбра на языке DOT. Внешняя программа `dot` рисует SVG. ASCII-дерево формируется с помощью стека.

## Сравнение с npm

```sh
python3 -m scripts.compare_npm
```

В Windows используйте `py -3 -m scripts.compare_npm`. Скрипт ставит каждый пример в отдельный временный каталог с `--ignore-scripts` и сравнивает множества вершин и рёбер с `npm ls --all --json`. Для сравнения npm запускается с исключением dev, optional и peer-зависимостей.

| Пакет | Вершины Python / npm | Рёбра Python / npm |
| --- | --- | --- |
| `is-odd@3.0.1` | 2 / 2 | 1 / 1 |
| `is-even@1.0.0` | 5 / 5 | 4 / 4 |
| `escape-string-regexp@5.0.0` | 1 / 1 | 0 / 0 |

При проверке совпали и количества, и сами пары `имя@версия` и рёбра. Отчёт сравнения с npm 10.8.2 сохранён в `examples/verified/npm-comparison.txt`.

Граф описывает объявленные зависимости из поля `dependencies`. Поддерживаются точные версии, теги реестра и обычные диапазоны SemVer (`^`, `~`, `x`, `*`, сравнения, интервалы с дефисом и `||`). Git/URL, локальные пакеты и npm-алиасы завершаются диагностикой при разрешении. При сравнении других пакетов на результат могут влиять правила установки npm, lock-файл, платформенные ограничения и необязательные или peer-зависимости. Если имя объявлено одновременно в `dependencies` и `optionalDependencies`, npm может использовать значение из второго поля. Реестр меняется со временем, поэтому версии транзитивных пакетов при повторном запуске могут отличаться.

В Windows замените `python3` на `py -3`. Тесты работают без интернета. Тест SVG пропускается при отсутствии `dot`. В истории Git есть отдельные коммиты для каждого из пяти этапов.
